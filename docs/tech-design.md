## 一、建设目标与业务边界

### 1.1 项目定位

以合法来源的家养梅花鹿为对象，建设支撑“良种繁育、规范养殖、鹿茸交付、联农服务”的数字化运营体系。系统服务于基地运营与投资决策，不以设备数量、大屏效果、模型演示或上链量作为建设成功标准。

一期必须形成两个可运营闭环：

- **种鹿闭环**：合法引种 → 身份与亲本证据 → 性能测定 → 选配繁育 → 选留/销售 → 检疫与交付 → 客户反馈。
- **鹿茸闭环**：投入品与健康管理 → 经批准的采茸操作 → 原料身份与称重 → 检测/质量审核 → 储运与销售 → 客户签收 → 异常冻结与召回。

合作户纳入同一业务与追溯体系，但不要求配置与示范场相同的传感器、视频和计算设备。

### 1.2 一期成果与价值

| 建设目标 | 交付能力 | 评价方式 |
|---|---|---|
| 种源与个体可管理 | 永久鹿ID、系谱、性能档案、选配与交付包 | 来源证据、亲本不确定性、记录完整性、选配过程可复核 |
| 生产与疫病风险可追责 | 人工巡检、免疫诊疗、引种隔离、异常工单 | 任务及时性、处置时长、漏报复盘；不以“零发病”作为软件承诺 |
| 产品可交付、可追回 | 批次血缘、质量放行、库存销售、召回 | 受控负向测试及真实交易核对 |
| 人工负担有依据地降低 | 扫码、自动采集、规则告警与移动工单 | 对比相同生产条件下的工时、误报工作量与返工量 |
| 经营与联农可核算 | 轻量成本账、回款、10户试点工具和结算 | 客户交付、资金收付、单户损益和合同履约 |
| AI可验证、可退出 | 数据集、模型卡、影子运行与停用回滚 | 相对人工及简单规则基线的实际收益和安全性 |

### 1.3 范围划分

| 范围 | 一期规定 |
|---|---|
| 基地生产 | 身份、系谱、健康、繁育、性能测定、饲料、采茸、环境、资产必建 |
| 经营与销售 | 订单、库存、质量放行、交付、回款、成本必建，不延后至第5年 |
| 合作户 | 支持10户、12—18个月的业务试点；实际开户与投鹿按合同及合规条件批准 |
| 感知 | 必要环境与基础安防先行；穿戴、个体视频识别按场测范围扩展 |
| 自动化 | 本地安全规则可在专项验收后启用；AI只提示和生成待确认建议 |
| 产品处理 | 覆盖现有合法采收、储存及必要委托加工的数据交接；不因此承诺自建加工厂 |
| 对外服务 | 内部台账、授权B端交付、公开追溯、监管导出；外部API按实际协议接入 |
| 暂不纳入一期基础投资 | 自建屠宰/精深加工线、大规模文旅、机器人近身作业、全群高配穿戴 |
| 暂不纳入一期基础收益 | 未签订单、溯源品牌溢价、补贴兜底、对外SaaS和模型API收入 |
| 按需研发 | 发情辅助、产茸预测、健康异常模型；不作为基地正常运营的必要依赖 |

### 1.4 业务边界

- 系谱记录不等于血统鉴定；性能高不直接等于遗传育种值高。
- 设备在线不等于动物存活，信号消失不等于死亡或资产流失。
- 公共二维码可查不等于实物正品、产品合格或监管认证。
- 家养梅花鹿属于特种畜禽目录范围，不意味着所有来源、产品形式和销售用途均自动合法。
- 不将药用、食品、化妆品原料的要求混成同一产品许可模板。
- 养殖、生物安全、动物福利、产品质量约束优先于成本与销售目标。

## 二、现场基线、项目假设与设计原则

### 2.1 现场基线采集

项目启动15天内形成基线初稿，30天内完成影响选型的现场核实。

| 基线对象 | 必须确认的输入 | 产物与责任 |
|---|---|---|
| 场地与建筑 | 实际可用范围、权属、圈舍类型、隔离区、出入口、冷库、加工交接点 | 场区底图和资产清单；工程、场长 |
| 鹿群 | 当前/拟引种头数、性别、年龄、种用/商品用途、来源、分批到场计划 | 存栏与生产计划；育种、场长 |
| 生产流程 | 配种、产仔、采茸窗口；班次、捕捉/操作设施、现有台账 | SOP目录、年度生产日历；兽医、育种 |
| 水电网络 | 配电容量、断电历史、接地防雷、运营商信号、局域网和布线路径 | 工程勘测和故障保障方案；工程、物联网 |
| 设备与接口 | 在用设备、型号固件、协议、原始数据出口、校准及服务期限 | 设备台账和协议矩阵；物联网 |
| 客户与产品 | 实际规格、用途、交付文件、检测要求、账期、包装单位 | 产品规格及交付模板；销售、质量 |
| 人员与数据 | 岗位资质、每班人手、历史记录质量、数据权属 | 人员排班、迁移清单；场长、数据负责人 |

### 2.2 规模与假设管理

- 800头与1600头仅作为既有材料中的容量测算场景，不代表已批准引种规模。
- 一期可从少量有代表性的圈舍进行工程试点。试点覆盖繁育、普通饲养及必要隔离监测场景，具体头数和点位由兽医、工程共同批准。
- 工程试点样本不自动满足AI统计要求；模型样本由实际事件率、群组差异和验证精度设计。
- 种鹿价格、鹿茸价格、租金、折旧、人工、设备寿命只引用批准的假设版本，均记录单位、年份、产品状态、数据来源和责任人。
- 尚未冻结的输入进入附录C，超过规定决策门仍未确认时，暂停依赖该输入的采购或上线，不自行填入“市场平均值”。

### 2.3 六项设计原则

1. **领域模型先定义，成熟工程先落地**：用实体、关系、事件和动作约束统一语义，不把关系库、表单和事务视为AI的对立面。
2. **一个事实源，多种业务视图**：生产、经营、质量共用事实，分别授权和分析。
3. **个体、批次、单件分层管理**：不同身份解决不同业务问题，不用一个短码包办全部场景。
4. **本地安全自治，云端辅助协同**：控制器不依赖云端在线或模型可用才能维持安全运行。
5. **观测、推断、确认分离**：机器观测、AI建议、兽医/业务确认均保留来源与版本。
6. **可渐进、可替换、可退出**：昂贵设备、AI、图库、存证按验证结果接入，失败不影响基础台账与正常生产。

## 三、总体架构与技术路线

### 3.1 分层架构

```text
业务与专业约束
合法来源 / 生产SOP / 质量规则 / 合同 / 人员授权 / 年度生产计划
                              ↓
应用层
养殖工作台 | 良种繁育 | 质量追溯 | 经营管理 | 农户移动端
授权B端交付 | 脱敏公众查询 | 监管报送/导出
                              ↓
领域服务层：模块化单体，清晰模块边界
主数据与身份 | 生产繁育 | 诊疗防疫 | 采茸批次 | 库存订单
放行召回 | 标签编码 | 工单调度 | 农户结算 | 权限审计
                              ↓
统一事实底座
关系数据库 + 业务事件/更正日志 + 附件对象存储 + 时序分区
          ├─ 可重建的查询/图谱/经营视图
          ├─ 规则与AI辅助服务：读事实，写建议
          └─ 异步存证适配：可选，不阻断核心交易
                              ↑
接入与边缘层
设备适配 / 身份解析 / 质量校验 / 持久化缓冲 / 幂等补传
                              ↑
现场感知与人工记录
环境 / 耳标或项圈 / 视频 / 称重 / 扫码 / 检验报告 / 巡检

独立控制通道：
批准的配置 → 本地安全控制器 → 执行器 → 状态反馈
                          ↑
                 现场联锁、人工接管、急停
AI建议 → 人工审批/工单，不直接进入执行器
```

### 3.2 双线与双场景

| 维度 | 设计 |
|---|---|
| 养殖执行线 | 围绕鹿只、圈舍、时间窗口安排防疫、繁育、采茸、巡检及异常处置 |
| 经营管理线 | 基于确认的资产、产量、库存、订单和收付款分析产能、成本及合作户履约 |
| 自有示范场 | 完整业务流程，选择性配置高质量感知，用于工艺、规则和模型验证 |
| 合作户网络 | 相同身份、关键事件、交付和结算语义；低负担录入、技术员复核和必要设备 |

两条线不分别维护存栏或库存真值。两类场景不按“自有即可信、农户即不可信”一刀切，数据质量依据校准、证据与复核确定。

### 3.3 一期技术基线

| 层次 | 默认选择 | 边界 |
|---|---|---|
| 业务服务 | 模块化单体、明确模块API、后台异步任务 | 首期不以微服务数量衡量先进性；独立扩缩容或团队边界确有需求再拆分 |
| 事务与台账 | PostgreSQL类关系数据库，事务、约束、行级锁、按需分区 | 最终产品结合支持能力及采购要求确认；不强行同时建设多套主库 |
| 业务事件 | 事务内写业务记录和Outbox，异步分发给查询、通知、存证 | 不要求一开始实现全量事件溯源架构 |
| 附件 | 对象存储、版本/哈希、访问授权 | 检验报告、照片与视频证据原件不能只保留链接或哈希 |
| 时序数据 | 首期分区表/时序扩展，达到容量或查询瓶颈后独立 | 采集量按现场配置测算 |
| 图谱 | 统一关系定义和图查询能力；专用图库暂非必建 | 若引入，作为从事实库重建的投影，不产生第二事实源 |
| 设备接入 | 环境可用RS485/Modbus，设备按真实协议适配；汇聚后MQTT over TLS或HTTPS | 遗留现场协议置于隔离网络，不直接暴露公网 |
| 边缘 | 网关、持久化队列、必要录像；视频推理按PoC确定算力 | 不因方案写有CV就整场采购GPU |
| 应用端 | 管理Web、现场移动端、公众H5 | 现场弱网端必须具备受控本地保存和补传，不能只做在线表单 |
| AI | 规则基线、离线训练/评估、独立推理、模型版本管理 | 不默认引入联邦学习、图神经网络或大模型集群 |
| 存证 | 审计、更正和可验证备份必建；第三方存证适配可选 | 不自建联盟链作为一期前置 |

### 3.4 关键架构约束

- 任何模块不得绕过领域服务直接修改库存、质量状态、身份绑定和已确认事件。
- 授权动作携带操作者、组织范围、业务版本、原因和请求标识。
- AI、报表、公众查询、存证失败不能阻断已批准的本地安全控制。
- 库存及质量交易成功由事务提交决定，不由消息推送、上链或页面刷新决定。
- 数据同步采用可重试的“至少一次传输+业务幂等”，不宣称网络链路天然恰好一次。
- 对外展示可使用只读投影，但出库、解除冻结等安全关键动作必须读取权威状态。

## 四、领域本体、主数据与身份体系

### 4.1 本体落地方法

本体在V2中是“实体定义、关系、事件、受控动作及规则”的统一业务契约，首先以数据字典和领域模型实现，不绑定特定平台。

每条专业规则记录：适用对象、输入条件、证据来源、规则版本、提出人、审核人、有效期、禁用条件及关联测试。明确区分法规约束、专业SOP、统计关联和试验假设。

规则升级流程为：提出 → 专业复核 → 回放测试 → 批准 → 有限范围发布 → 观察 → 扩大或回滚。历史决策保留原版本，不能因规则更新改写过去的依据。

### 4.2 核心实体

| 实体 | 作用 | 关键关系 |
|---|---|---|
| 租户/组织 | 数据管理与责任主体 | 可管理多个场区、合作户和客户；组织边界不等于物理圈舍 |
| 场区/生产单元/圈舍 | 地址、生产责任与实际空间 | 一个合作户可以有多个生产单元；生产单元内有多个圈舍 |
| 个体鹿 | 永久身份、来源、品种、性别、出生、状态 | 亲本、设备绑定、在栏、所有权、托管、生产事件 |
| 亲本关系/遗传样本 | 记录父母候选、确认及证据 | 关系可为未知、候选、已确认、已更正 |
| 人员与角色 | 业务操作和专业责任 | 资格、任职、组织授权、工作班次 |
| 设备/校准记录 | 测量与控制资产 | 位置、动物绑定、协议、固件、校准、维修 |
| 投入品批次 | 饲料原料、药品疫苗、冻精等 | 供应商、接收、自制、领用、消耗、停用 |
| 生产事件 | 出生、转群、繁育、巡检、投喂、采茸等 | 发生对象、时间、人员、证据与更正 |
| 样本/检测报告 | 检验对象与质量证据 | 采样单、实验室、项目、适用批次、审核 |
| 原料/加工/成品批次 | 产品追溯与数量核算 | 来源采收、输入输出、工艺、质量和库存 |
| 销售单元/标签实例 | 具体实物交付与识读 | 所属批次、净重、包装、标签替换和公开码 |
| 库存流水/订单/发运 | 物权、保管、数量、客户流向 | 预留、出入库、交接、签收、退货 |
| 质量限制/召回案 | 不合格、待核、休药相关约束与追回 | 适用对象、上下游影响、处置责任和结果 |
| 合同/结算 | 合作户及客户履约 | 定价版本、质量确认、应收应付、争议 |
| 告警/工单/控制命令 | 从监测到处置 | 规则/模型证据、受理、执行、验证 |

### 4.3 身份与编码分层

**项目内部主键采用UUIDv4等价的128位随机标识，具体实现统一为UUIDv4；所有对象受数据库唯一约束保护。**

| 标识 | 生成与约束 | 生命周期 |
|---|---|---|
| `animal_id` | 中心或受控离线客户端生成UUIDv4；同步时核验真实鹿只是否已有档案 | 终身不变，不随换标、转场、售出、死亡而回收 |
| `device_id` | 设备资产ID，厂商序列号作为外部属性 | 可维修替换；同一设备同时只能有效绑定一头鹿，允许解绑后受控重用 |
| `event_id`、`batch_id` | UUIDv4；事件与批次分别生成 | 已确认后不回收；更正创建新记录并引用原记录 |
| `sales_unit_id` | 每个最小销售单元独立UUIDv4 | 包装实物不变时保持；拆包再分装形成新单元并记录来源 |
| `label_id` | 每张物理标签的独立实例ID | 补打产生新标签实例，旧实例作废且保留历史 |
| `public_token` | 中心用密码学安全随机源生成128位随机数，32位小写十六进制表示；全局唯一校验 | 映射一个标签实例及其目标；不作为身份认证凭据 |
| 外部码/商品标识 | `(issuer, scheme, version, code)`命名空间约束，映射内部对象 | 已使用映射不重新分配；供应商和监管原码原样留存 |

展示可使用短名称或业务别名辅助人工操作，但唯一识别和扫码以完整标识为准。短显示名不能被当作去重依据。

发现重复建档时，冻结冲突档案的交易和标签动作，人工核对实物与历史证据后建立主档及别名关系；不得仅按设备号、生日或照片自动合并。

### 4.4 时态关系与存栏

- 设备绑定、圈舍居住、所有权、托管关系均记录`valid_from`、`valid_to`及记录时间。
- 鹿只跨圈舍转移通过转群事件关闭旧关系、建立新关系；运输期间明确“在途”，不伪造同时居住两处。
- 存栏变更只由已确认的出生、引入、调入、调出、死亡及更正事件产生；设备离线仅产生核实任务。
- 母本、父本候选及确认记录带证据类型；群配场景无法确认父本时保留候选或未知。
- 投喂事件关联“饲料批次—圈舍/实际对象—时间—数量”，再结合历史在栏关系得到**可能暴露鹿只**，不得据此虚构每头鹿的实测采食量。
- 环境指标与健康事件的关系默认属于关联和风险提示，不预置为已经证明的因果关系。

### 4.5 不可违反的业务规则

1. 一头鹿可以同时有多个用途不同的识别装置，但同一装置不得同时归属于两头鹿。
2. 死亡、售出、标签作废等状态保留全部历史，不能通过删除主档“清理数据”。
3. 来源未知不自动转为来源合格，父本未知不自动补齐为推荐种公鹿。
4. 生产批次关系形成有向无环图，不允许批次成为自己的来源。
5. 未放行、有活动限制或来源存在限制的对象不得销售出库。
6. 兽医和质量限制不能被经营管理员、供应商或模型直接解除。
7. 物理在库、质量放行和所有权是不同维度，任何一项不能替代其他条件。

## 五、良种繁育与生产业务闭环

### 5.1 引种与建档

流程：供应商核验 → 合同与来源材料 → 运输及检疫资料审核 → 到场清点 → 永久身份核对 → 隔离观察/检测 → 兽医批准入群。

记录供应商、外部耳号、品种与证据、性别、出生日期或估计范围、亲本、体况、检疫材料、到场时间、运输责任、隔离圈舍及处置结果。身份不确定、资料缺失、检测未完成时标为待核，不允许按已合格种鹿销售。

隔离时长、检测项目和入群标准由专业SOP及实际适用要求确定，软件提供计划、到期提醒和阻断，不自行设定通用天数。

### 5.2 良种目标与性能测定

| 管理内容 | 设计要求 |
|---|---|
| 选育目标 | 育种负责人确定产茸、繁殖、成活、健康和适应性等目标及权重；单纯追求茸重不能覆盖健康约束 |
| 基础测定 | 出生、阶段体重、体尺、体况、年龄、饲养组、季节、测量方法和操作者 |
| 产茸测定 | 鹿ID、采收日期、当次/累计次数、鲜/干状态、毛重/皮重/净重、茸型、等级依据、样本与报告 |
| 生殖记录 | 发情确认、选配、配种方式与种公鹿/冻精批次、妊检、分娩、产仔、育成和异常 |
| 亲本核验 | 记录现场配种、出生观察、外部证书及必要的样本/亲子鉴定；置信不足不得出确定系谱证明 |
| 选配控制 | 根据可用代际、近交风险、疾病限制、年龄和容量筛选；缺失系谱时显示不确定性并人工审批 |
| 遗传评估 | 一期以可比较性能和系谱证据为主；数据充分后由育种专家选择遗传评价方法，报告可靠度及群体适用范围 |
| 选留淘汰 | 形成推荐名单、理由、审批和实际处置事件；算法不能自行出售或淘汰鹿只 |

**标准化不等于强行频繁测量**：测定频率应结合必要性、捕捉操作与应激风险制定，能复用生产机会的测量不重复扰动动物。

### 5.3 繁育状态与任务

```text
待评估 → 可配种 → 配种计划 → 已配种 → 待妊检
                                      ├─ 妊娠确认 → 待产 → 分娩记录 → 哺育/断奶
                                      └─ 未确认/复查 → 兽医与育种负责人重新评估
```

- AI疑似发情独立保存在建议层，不直接推动“已配种”或“妊娠确认”。
- 计划任务关联季节、个体状态与专业SOP，临床异常转诊疗工单。
- 新生鹿建档关联母鹿与出生事件；父本不确定可暂缺，但缺失原因必填。
- 成活率、受胎率、产仔率分别记录分母、时间窗口和纳入对象，不用同一个“繁殖率”替代所有指标。

### 5.4 饲料、用水与投入品

- 饲料、原料、冻精、药品和疫苗分品类管理接收、储存条件、有效期、资质适用性、领用和报废。
- 自制饲料记录配方版本、原料批次、数量、制作时间、负责人及产出批次。
- 一期饲喂以圈舍/群组计划、实际投放、余料、异常和责任人构成闭环；没有个体计量设施，不展示“个体真实摄入量”。
- 饮水与供水故障纳入巡检和必要监测；断电断网时仍须有现场保障与人工应急。
- 投入品召回可顺查使用时间、圈舍、在栏鹿只及后续产品，形成待评估暴露范围。

### 5.5 健康、防疫与净化记录

流程：计划或异常发现 → 观察/采样 → 兽医评估 → 诊疗处置 → 用药及限制 → 复查 → 关闭或继续观察。

记录症状、发现时间、操作者、诊断与疑似状态、样本、处方及施药责任、药品批次、剂量单位、处置、复查和适用产品限制。限制覆盖哪些产品及解除依据由兽医与质量负责人共同维护，不采用一个默认休药期套用所有药物和用途。

口蹄疫、布鲁氏菌病等监测、净化与人员防护计划由专业团队按适用要求制定。系统记录计划、抽样对象、送检、结果、报告及处置，不能以“无AI告警”证明动物无疫。

### 5.6 采茸与种鹿交付

**采茸作业**：排程建议 → 兽医/生产条件确认 → 个体身份复核 → 按批准SOP执行 → 称重与来源标识 → 原料批次登记 → 质量待检入库。

记录操作人、时间、工具消毒、必要用药、异常及恢复观察；涉及专业操作的权限和资质按SOP限制。软件不生成未经批准的药物、剂量或采茸操作方案。

**种鹿交付包**：永久ID及外部标识、来源与亲本证据、品种声明依据、测定记录、繁育/健康摘要、适用检疫材料、交接双方、运输与签收。内部完整诊疗细节按必要范围授权，不全部公开。

## 六、产品批次、质量放行与召回

### 6.1 批次层级

```text
鹿只 → 采茸事件 → 原料批次
                     ├─ 整批交付 → 销售单元/容器 → 客户
                     └─ 合法加工/委托加工 → 加工批次 → 成品批次
                                                      ↓
                                            最小销售单元 → 装箱 → 发运
```

- 采茸事件与原料批次分离：一次采收可形成多个带来源标识的原料项；多个采收进入同一批次须满足批准的合批规则。
- 质量和召回粒度由工艺、卫生隔离、时间窗口及客户要求决定，不为适配短码容量任意合批。
- 同一原料分割、加工或包装后产生新的输出对象，保留每次转换输入、输出与数量。
- 原料身份不明时先隔离；不得人工选择“相近鹿只”补齐来源。

### 6.2 质量与库存状态分离

| 状态维度 | 状态及规则 |
|---|---|
| 质量评估 | `PENDING`待审核、`RELEASED`已放行、`REJECTED`不合格；放行记录带用途、规则版本和证据 |
| 活动限制 | 独立的`hold`集合：检测待核、药物影响、冷链异常、来源争议、召回等；多项限制需分别解除 |
| 物理库存 | 在库、在途、已交付、已消耗、已处置等，由流水和交接决定 |
| 可售量 | 实际在库减已预留量，且本对象及适用来源链均允许目标用途；不是单个可手改字段 |
| 召回案 | 草拟、已启动、执行中、待复核、已关闭；关闭案不自动恢复产品可售 |

检测不合格不一定立即物理报废，先限制再按专业决定处置；已出库产品发生冻结仍保留交付记录，并进入召回评估。

### 6.3 检测与放行

1. 采样单明确对象、批次/单件、采样方式、时间、采样人、样本ID及交接。
2. 报告记录实验室、项目、方法、结果、签发时间、原件、适用范围及审核人。
3. 放行人核验来源、采收条件、检测、用途、有效证照、药物限制、储运和客户要求。
4. 满足全部条件后，形成针对对象和用途的放行记录；变更加工方式、用途或新增质量风险时重新评估。
5. 快检作为筛查信息，不默认替代正式检验；一份报告能覆盖哪些对象必须有采样和规则依据。
6. 未满足条件时界面显示具体阻断理由，禁止通过调整订单类型或重打标签绕过。

### 6.4 出库事务与并发冻结

出库在**中心权威服务在线**时确认，不允许离线终端依据旧状态批准销售。

中心在线不代表所有现场信息已经同步。出库前必须确认相关采收、用药、检测、交接等关键记录已同步并复核至该批次的放行截止点；源场存在未对账离线业务、接收水位异常或未解除的数据完整性限制时，不能仅依据中心旧记录放行。相关现场负责人提交交接确认，质量负责人审核；紧急健康事件另有电话等通知路径，不能只依赖客户端恢复联网。

在同一数据库事务中完成：

- 身份、组织、订单、收货方和用途授权；
- 库存、预留、数量和计量单位校验；
- 本对象及适用祖先批次的质量、活动限制和凭证检查；
- 库存扣减、发运记录、来源快照和Outbox写入。

批次关系在确认后不可静默改写。冻结根对象时，先原子写入限制及状态版本，再异步展开影响清单。出库不依赖展开完成，而是即时校验来源链。

冻结、加工输出确认和出库使用统一顺序锁定相关批次/来源对象并检查版本，避免“读到可售后恰好被另一操作冻结”仍然通过。并发测试必须覆盖两种提交先后：冻结先提交则出库失败；出库先提交则进入已发运影响清单和召回流程。

系统扣库和物理离场分开记录。完成电子出库后处于待交接/待离场状态，离场扫码或交接确认再在线复核活动限制；期间发生冻结则停止交接、原地隔离并以补偿流水处理库存。实物已经交付或在途后才发现限制，转入拦截/召回，不能删除出库记录伪装为从未发出。

### 6.5 数量核算与跨主体交接

- 所有称重保留毛重、皮重、净重、单位、分度/校准信息、称重时间和设备；不得将显示1g误称为全量程准确度1g。
- 鲜茸、干茸、切片及提取等对象分别记录产品状态、水分/工艺依据和计量单位；不要求不同状态机械等重。
- 转换记录满足“输入量—输出量—留样—废弃/损耗”的可解释核算；差异超批准阈值进入复核。
- 合作户、委托加工商、物流与客户之间使用双方标识映射、交接单及数量核对；平台外环节至少获取可验证交付凭证。
- 外部伙伴无法提供批次映射时降低追溯完整性声明，限制需要完整证据的产品放行，不虚构全链路。

### 6.6 召回闭环

触发：不合格报告、质量投诉、受影响投入品、冷链失效、身份错误或依法收到的监管指令。

```text
立案 → 冻结已知对象 → 计算后续批次/单件/客户 → 复核并启动通知
     → 在库隔离 / 在途拦截 / 客户追回 → 数量核对 → 处置与复核 → 关闭
```

每个影响对象记录应追回量、已隔离量、已追回量、已消耗/处置量、未追回量、原因、联系人和下一动作。关闭必须由质量负责人确认差异及处置，不以通知已发送或二维码页面已更新作为完成。

**受控示例**：两头鹿的原料合为一批，分装10件，其中6件出库、4件在库；源头新增质量限制后，4件立即不可出库，6件进入客户清单。收回2件时，案卷显示2件已回、4件待追，不将全部10件标成“已召回”。示例仅验证系统关系和数量逻辑。

## 七、追溯编码、标签与可信查询

### 7.1 V2默认编码方案

**默认使用内部永久ID + 独立销售单元ID + HTTPS公开标签码。20位参考编码不是一期必建，也不作为主键。**

二维码载荷示意：

```text
https://trace.example.invalid/t/v2/{public_token}
```

该域名仅为格式占位，不可打印上线。正式域名须由项目责任主体持有或具备持续使用权，TLS证书、DNS、续费、迁移和扫码服务维护纳入合同。

解析规则：

1. 校验固定路径版本和32位十六进制token格式。
2. 查询唯一标签实例，再解析目标批次/销售单元；不从token中推算用户身份或权限。
3. 返回代码登记、标签状态、产品概要、最新质量提示及更新时间。
4. 标签作废、疑似复制、召回或状态不可确认时明确提示，不显示默认“正品”。
5. 详细报告与交付材料另行登录授权；公开token不能用于后台接口鉴权。

一期对外正式标签由中心生成并激活。离线采收先使用受控临时内部标识，恢复网络并确认来源后再生成正式标签；不允许离线扩增对外码段。

### 7.2 外部编码兼容

| 情况 | 处理 |
|---|---|
| 客户不要求标准商品编码 | 使用V2项目码，不宣称其即为GS1或某项国标认证码 |
| 已有合法GTIN | 留存分配主体和商品映射；按采用的规范生成/读取商品数据，不任意随机“生成GTIN” |
| 客户要求GS1等编码 | 建立独立编码适配版本并做规范符合性及扫码测试，业务身份仍使用内部主键 |
| 客户确需参考20位编码 | 经书面约定启用兼容模块，明确编码责任、批次粒度、容量和溢出策略 |
| 外部标准或对接格式变化 | 新增`scheme/version`适配，不批量替换历史内部ID；历史码保持可查 |

20位兼容模式中，年月4位与批次2位在其他字段相同时最多100种。第101个批次必须报容量超限，不重码、不回收旧码、不虚增产品种类。业务可继续使用内部身份，但未满足合同外码要求时不得完成对应交付。

### 7.3 标签内容与工位设计

| 标签类型 | 内容与用途 |
|---|---|
| 鹿只可视标识 | 可读个体号/辅助码、内部扫码标识；与永久鹿ID绑定，符合现场识别和专业管理要求 |
| 原料内部标签 | 原料/批次ID、来源、采收时间、产品状态、重量、责任工位；明确“待检/内部使用” |
| 外部产品标签 | 产品真实名称、责任主体、批次/单件标识、适用日期与规格、二维码、必要质量与用途标识 |
| 物流包装标签 | 箱/容器ID、所含销售单元清单、数量及交接信息 |

- 产品法定标签内容按实际品类与用途确定，追溯标签不能替代法定标签。
- 不默认采用“溯源身份证”字样，不无依据标注监制、地理标志、认证或功效。
- 参考稿的4cm×2cm、文字1.8mm可用于首轮打样比较，不作为全部包装的统一验收门槛；以适用规则、码密度、留白、识读设备、可读性及环境试验确定。
- 材质按低温、冷凝、摩擦、湿度和包装接触要求验证；直接接触产品的材料另核相容与安全要求。
- 一期优先热转印打印、人工扫码核对和贴标；喷码、自动贴标、固定通道根据真实吞吐再采购。

### 7.4 标签与防伪生命周期

`已生成 → 已打印 → 已核对绑定 → 已激活 → 已作废/替换`

- 打印任务记录数量、设备、操作者、打印结果、领用及报废；激活前复核实际物件。
- 标签激活只表示身份绑定有效，不表示质量已放行。待检产品若已绑定标签，查询页必须显示待检/不可售；出库仍执行独立质量门禁。
- 同一销售单元可保留多个历史标签，但同一用途只保留一个有效外部标签实例；补打先受控作废旧实例。
- 补打不能解除召回或质量限制，不能改变产品生产日期和来源。
- 防伪层与追溯层分开：高价值产品可增加防转移材料、隐藏验证码或其他经验证特征，是否采用由成本与客户需求决定。
- 扫码次数和异常访问只构成风险线索，不能凭异地访问或多次扫码直接认定假货；不为防伪默认收集精确个人位置。
- 防伪指标依据实际采用的现行规范和合同测试方法，禁止将旧版“B级”等机械套用为厂商资质。

### 7.5 可信存证

必建能力：操作审计、原始附件保存、文件哈希、业务更正链、备份恢复及访问记录。

可选第三方存证只处理已确认关键事件的摘要，包括个体/批次引用、原件哈希、算法与规范化版本、时间信息、操作者及证据编号。失败进入重试和人工处理，不回滚已提交的正常业务事实。

更正产生新版本和原因，同时保留原记录及原证明。第三方时间戳或链上时间不等于实际采收时间，不能用存证覆盖事实发生时间。

存证仅支持“内容与已留存版本是否一致”的核验，不自动证明源头数据、血统、产品品质或实物真伪。

## 八、感知设备、网络与现场工程

### 8.1 部署策略

1. 先完成生产身份、场区底图和关键操作点设计，再确定感知点位。
2. 必要环境监测、基础安防和操作工位优先；穿戴与CV在代表性场景验证后扩大。
3. 对隔离舍、重点繁育区、冷库、供水和关键设备单独核算覆盖与保障，不能以全场平均掩盖薄弱点。
4. 不以一次安装“无感”作为承诺。佩戴、换电池、拆卸、清洁与生长适配均纳入动物福利和维护计划。

### 8.2 场景—设备—协议矩阵

| 场景 | 感知/操作设备 | 实际链路 | 一期能力边界 |
|---|---|---|---|
| 圈舍环境 | 温湿度及按风险配置的氨气/CO₂等探头 | RS485/Modbus或厂商明确协议 → 本地控制/网关 | 连续监测、阈值提示；量程、位置与维护方式需场测 |
| 个体温度/活动 | BLE耳标候选 | 耳标 → BLE网关 → 以太网/4G → 中心 | 耳部测量与活动趋势；不默认等于核心体温 |
| 远距离低功耗采集 | LoRaWAN耳标/节点候选 | 匹配频段/协议的节点 → LoRaWAN网关及网络服务 → 中心 | 只有确认终端匹配和区域使用要求后才部署 |
| 定位 | 4G GNSS项圈候选 | 项圈自身4G → 经授权的服务/中心 | 与LoRaWAN网关无默认依赖；定位更新和端侧告警待证 |
| 视频 | 网络相机、录像/边缘推理节点 | 场区有线网络优先，验证视频协议 | 行为或区域监测；未识别个体时只报圈舍异常 |
| 活体称重 | 专用安全通道和适配量程的秤 | 扫码/识别 + 称重接口 → 边缘终端 | 与低应激通道配套，不与茸重秤混用 |
| 采茸计量 | 适合茸重范围的电子秤和扫码终端 | 受支持的串口/USB/网络接口 → 工位应用 | 身份、重量、单位、操作记录同步 |
| 产品冷链 | 冷库/运输记录仪 | 本地记录 + 可用网络/回收导入 | 离线记录完整；超限进入质量复核 |
| 出入库与标签 | 打印机、PDA/扫码枪 | 场区网络 → 业务服务 | 逐件/容器识别；固定通道非默认必需 |

### 8.3 原方案设备的使用定位

S306-P-B、S508-H-C等型号仅保留为候选，不形成指定采购。

| 候选资料参数 | V2解释与准入要求 |
|---|---|
| S306-P-B默认60分钟上传、18个月续航、标称0.5℃ | 仅为资料规格；必须取得采样、广播、事件上报、校准、配置和功耗证据 |
| S508-H-C默认2小时上传、6个月续航、定位5—10m | 不承诺即时越界；林下遮挡、弱网、佩戴和事件上报需试验 |
| BLE网关标称100m稳定覆盖并带定位 | 覆盖受棚舍、地形和密度影响；网关坐标不是每头鹿坐标 |
| LoRaWAN标称公里级覆盖 | 不把标称距离当工程半径；端点、网关、频段、天线、供电、网络服务同时核验 |
| 39枚耳标短期测试说明 | 可作试点背景，不能证明整场长期零掉标、零丢包或全寿命续航 |

### 8.4 采样、上报和时延

| 数据类型 | 建议设计目标 | 不满足时处理 |
|---|---|---|
| 关键环境观测 | 可讨论10—30秒采样、60秒内本地异常提示；具体依据控制需求冻结 | 若探头更新率/响应时间不支持则换设备或调整能力，不仅修改软件轮询频率 |
| 耳部温度/活动 | 默认按设备已验证频率运行；若需5分钟上报另做功耗和数据有效性验证 | 未具备能力时展示小时级趋势，保留人工观察 |
| 定位 | 轨迹/资产观察与即时越界分开；定位模式和事件上报分别测试 | 没有端侧主动告警不承诺即时发现；保留实体防护 |
| 视频 | 分辨率、帧率、夜间表现、并发路数、识别范围按试点冻结 | 降为录像与圈舍级提示，不伪造个体识别 |
| 业务事件 | 现场及时记录，弱网本地持久化并显示待同步；时限按SOP | 超时催办，禁止以静默自动补录替代责任确认 |

设备采样间隔、上传间隔、传感器物理响应时间、网络耗时和人员响应时间分别计量，不用一个“实时”笼统描述。

### 8.5 场测与采购准入

必须提交：

- 代表性圈舍、密集动物、昼夜、遮挡和弱网测试记录；
- 与适当参考测量对照的偏差、重复性、环境影响；0.3℃变化阈值未验证前不得上线；
- 丢包、重复、补传、时间漂移、设备换绑和低电预警结果；
- 修改上报频率后的电池消耗估计和维护负担；
- 佩戴不适、脱落、磨损、惊跳和恢复记录；
- 协议文档、原始数据样本、版本、升级方式及退出授权。

连续30天可作为工程试运行建议周期，但不能替代季节或寿命验证。出现装置相关严重伤害或现场安全故障立即停用对应装置并专业复核。

### 8.6 供电与网络工程

- 固定工位和视频优先使用经勘测的有线网络；无线接入按覆盖和故障场景补充，不将5G作为必需技术。
- 工业现场、业务终端、视频、管理运维和公众服务分区；控制器不接受来自公网的任意连接。
- 网关、电源、机柜、线缆、接地、防雷、防水、防腐和防啃咬按现场条件设计。
- UPS保障范围和持续时间按实际负载核算；网关续航不等于风机、水泵或加热设备可持续运行。
- 太阳能方案验证阴雨天储能和负载，不以“太阳能供电”代替备用方案。

## 九、安全控制、告警与生产调度

### 9.1 自动化等级

| 等级 | 能力 | 一期使用条件 |
|---|---|---|
| L0 只读监测 | 记录、看板、告警 | 数据有效性及基本安全通过 |
| L1 人工闭环 | 规则/AI提示 → 工单 → 人工处置 → 复核 | 岗位、值班、证据和升级链路明确 |
| L2 本地规则控制 | 本地控制器执行已批准环境控制逻辑 | 专项联锁、断网断电和接管验收通过；不使用AI直接决策 |
| L3 AI闭环优化 | 模型自动调整控制目标 | 不纳入一期，需独立安全论证、试验和授权 |

### 9.2 控制权与安全状态

优先级：硬件保护/急停与安全联锁 → 授权现场接管 → 批准的本地自动规则 → 受控远程操作。人工接管也不得绕过必要硬件保护。

每台设备配置控制档案：责任人、允许操作角色、工作模式、正常范围、安全状态、启停间隔、上下限、联锁条件、超时、反馈点、告警和恢复流程。

- 风机、喷淋、加热、供水等分别确定安全策略，不能统一“断网全部关闭”。
- 远程命令包含`command_id`、目标设备、设定值、审批依据、状态版本及`expires_at`。
- 控制器校验模式、互锁、数据新鲜度和命令时效，不执行重复或过期命令。
- 云端失联继续运行最近批准且有效的本地配置；配置失效、探头冲突或关键反馈丢失时进入批准的降级模式并现场告警。
- 模型停用只撤销模型建议，不解除现场安全规则。

### 9.3 命令闭环

`已申请 → 已授权 → 已发送 → 已接收 → 执行中 → 已执行 → 效果验证`

失败、超时、拒绝、取消独立记录。网络投递成功不等于已执行，执行回执不等于生产效果达标；缺反馈时生成核实工单。

### 9.4 告警与工单

| 告警类型 | 主要责任 | 处理 |
|---|---|---|
| 数据/设备异常 | 维护人员 | 查电量、网络、探头、绑定；不得直接作动物诊断 |
| 生产关注 | 饲养员/场长 | 核实个体或圈舍，记录观察 |
| 健康风险 | 兽医 | 专业评估、必要检测和处置 |
| 环境/设施安全 | 场长、工程 | 本地安全措施、确认设备状态 |
| 产品质量 | 质量负责人 | 冻结、评估、放行或召回 |

工单状态：新建 → 待受理 → 已受理 → 处置中 → 待复核 → 已关闭；同时允许有原因的误报、重复合并、转派、撤回和重新打开。

告警按对象、规则和时间窗口去重，关联多条证据，设置迟滞与恢复条件。不得通过简单静默掩盖持续异常。紧急类型需验证本地声光或其他适用通知、值班联系方式和无人受理升级，不只依赖单个手机推送。

具体受理和到场时限按交通、班次、风险冻结；试验前确认每班可承担工单量。人员不足时限制模型告警范围，而不是强行增加无人处理的消息。

### 9.5 人工兜底

保留每日生产巡检、隔离观察、饮水与围栏检查、专业操作和质量放行岗位。巡检次数调整必须在安全和实际工作量验证后批准，不在AI试用阶段预先裁减。

## 十、AI辅助决策与验证体系

### 10.1 能力路线

先建立人工流程和可解释规则基线，再评价模型增益。AI输出必须携带适用对象、证据窗口、数据质量、模型/规则版本、风险等级、置信/不确定性、建议及禁用说明。

若仅有未校准分数，标为风险评分而非“发生概率”。不输出无依据的0.83概率或固定“24—72小时提前发现”承诺。

### 10.2 三类模型

| 模型 | 输入与输出 | 标签与评价 | 上线边界 |
|---|---|---|---|
| 健康异常辅助 | 经验证温度、活动、观察和环境 → 待核实异常 | 兽医复核/必要检测；事件召回、精确率、每100鹿日误报、漏报分析、提前量分布 | 不自动诊断病种，不替代防疫计划和巡检 |
| 发情辅助 | 行为、趋势、周期与繁育窗口 → 候选个体及观察任务 | 专业确认事件；事件级召回/精确率、窗口偏差，受胎效果另评估 | 不直接安排未经审核的配种或药物干预，不套用牛场92% |
| 产茸预测 | 可用历史产量、年龄、测定、季节和饲养信息 → 产量/等级区间及采收计划建议 | 独立实际采收；MAE、加权误差、区间覆盖、等级混淆 | 输入不得含采后信息；实际采收条件仍由专业人员确认 |

### 10.3 数据与试验设计

1. 明确事件定义、目标时间、纳入/排除标准、验证对象和最小信息。
2. 建立标注规范，记录首位标注者、复核者、分歧及仲裁；与模型预测分离，避免先看结果再改真值。
3. 按个体、圈舍/群组和时间划分训练、调参及冻结测试集，防止同一动物相邻视频帧泄漏到测试集。
4. 试验前冻结基线、指标、误报预算和必要样本；样本不足只能评为证据不足。
5. 按年龄、性别、季节、设备和场地分层检查，报告置信区间与失败案例。
6. 真值与预测均保留时间，提前量按事先定义的确认事件计算，不事后更改参照点。
7. 健康改善、产茸增加与受胎改善需考虑饲料、人员、季节等混杂因素，不把相关性直接表述为AI因果收益。
8. 不为采集疾病样本主动诱发风险；遇不到足够事件可延长观察，不降低标准凑数。

### 10.4 发布与停止条件

`离线验证 → 影子运行 → 少量人工辅助 → 评估扩大 → 持续监控`

影子运行只记录建议，不影响真实操作。每个模型独立签批、独立停用，不要求三个模型同时通过。

下列情况停止建议或降为人工：关键输入缺失/过期、身份不确定、超适用群体、设备或规则大幅变更、误报超承载、严重漏报、数据漂移或模型服务异常。

发布保留前一稳定版本和复现数据；回滚后工单仍保留原模型证据。用户反馈进入待审核标签池，不直接在线自学习。

### 10.5 知识助手边界

如后续引入大模型，仅用于已授权SOP检索、档案摘要、任务草稿和带出处解释；不生成自主处方，不获得付款、质量放行、身份更改和执行器操作权限。外部文档和用户上传内容视为数据，不作为自动调用工具的指令。

### 10.6 效果周期

90天主要验证数据、规则和工程流程；发情、繁育和产茸效果按实际生物学周期评价。若未覆盖相关周期，不将模型演示包装为生产有效性验收。

## 十一、数据治理、接口与离线一致性

### 11.1 数据分层

| 层级 | 内容 | 写入与更正 |
|---|---|---|
| 原始观测 | 探头数值、设备报文、视频、人工原始记录 | 保留来源和接收时间；异常标记不等于删除 |
| 规范化数据 | 单位转换、校准结果、身份与时态关联 | 记录转换版本，可从原始数据重建 |
| 推断建议 | 模型评分、规则触发、候选事件 | 不覆盖事实；记录模型版本和证据 |
| 已确认业务事实 | 兽医确认、繁育操作、交付、放行等 | 授权动作提交；更正有新记录、原因和审批 |
| 查询/分析投影 | 图谱、看板、经营分析、公众展示 | 从事实重建，记录同步位置和更新时间 |

数据质量用来源、校准、完整性、新鲜度、身份可信度、复核状态等标签组合表示。人工确认和实验室结果可能作为真值；设备自动采集也可能因脱落、故障和环境影响不合格。

### 11.2 通用事件契约

| 字段 | 含义 |
|---|---|
| `event_id`、`event_type`、`schema_version` | 全局事件身份、类型、载荷版本 |
| `tenant_id`、`org_id`、`site_id` | 授权域与责任场区 |
| `subject_type`、`subject_id` | 关联对象；多对象在明细中显式关联 |
| `occurred_at`、`recorded_at`、`received_at` | 实际发生、现场记录、中心接收时间；统一存UTC，按Asia/Shanghai展示 |
| `source_type`、`device_id`、`device_sequence` | 人工/设备/外部系统来源；设备重启序列需带会话标识 |
| `actor_id`、`reviewer_id` | 操作与复核责任；机器来源明确系统身份 |
| `payload` | 数值、单位、对象明细、证据引用及业务字段 |
| `quality_flags`、`calibration_ref` | 缺失、异常、校准和身份质量信息 |
| `request_id`、`expected_version` | 重试幂等与乐观并发控制 |
| `evidence_refs`、`correction_of` | 原件、关联证据及更正对象 |

时间不可靠时记录估计范围与设备时钟质量，不用接收时间冒充发生时间。未知值使用明确缺失状态和原因，不用0替代。

### 11.3 离线策略

| 动作 | 断网时允许 | 中心恢复后的要求 |
|---|---|---|
| 观测/巡检/采茸记录 | 本地持久化，显示待同步 | 幂等补传、身份校验、冲突处理后入账 |
| 新生鹿/临时原料登记 | 可生成内部UUID，挂临时状态 | 去重、资料复核、批准后成为可交易对象 |
| 本地控制 | 执行已批准的本地安全策略 | 上报运行记录，不重放过期远程命令 |
| 质量放行/解冻/正式销售出库 | 禁止离线最终批准 | 在线读取最新限制和权威库存 |
| 正式公开标签发行激活 | 不允许离线发行；仅可按批准流程打印内部临时标识 | 中心核实、赋码、绑定和激活 |
| 结算付款 | 可收集草稿/交接材料，不自动付款 | 对账、审核、授权外部付款并留回执 |

离线界面区分“已保存本机”“中心已接收”“业务已确认”。只有持久化完成才提示保存成功；中心接收后业务校验失败必须展示原因，不能静默丢弃。

本地队列按实际速率至少验证建议72小时容量；空间不足预警，不覆盖未同步关键业务记录。视频可按批准留存策略轮转，业务事件和视频队列分开。

### 11.4 冲突与更正

- 相同幂等键、相同内容返回原结果；相同键、不同内容明确冲突。
- 转群、身份绑定、库存和质量状态用版本校验，冲突进入人工处理，不简单“最后写入覆盖”。
- 迟报投喂或用药可能改变历史暴露范围，触发后续产品风险重新评估和必要冻结。
- 业务交接维护各源场关键事件的接收与复核水位；放行所需记录不完整时自动或人工设立数据完整性限制，中心恢复在线不自动解除。
- 已发布关系或报告错误以更正/撤销记录处理，保留原证据和当时对外披露版本。
- 人员离职或设备替换不删除其历史责任记录；按合法目的控制后续访问。

### 11.5 内部接口基线

### 11.6 保存与数据出口

- 参考规程提出“上市后2年且不少于2个生产周期”，V2将其作为生产追溯记录留存策略的参考输入，不称作普遍法定期限。
- 核心生产追溯资料的删除日期按适用法律、合同、已采纳项目规则和争议留存要求中的更长期间确定；尚不能确定的核心档案不自动清理。
- 育种谱系、活体历史跨整个管理生命周期保存，并明确终止后的保存责任。
- 视频可讨论30天常规轮转、事件片段另行保留；人员和公众访问数据按必要目的及适用要求单独确定，不能套用生产档案长期留存。
- 备份也适用保留、删除和访问控制策略。暂停删除的争议或召回对象应有法律/业务保全标记。
- 提供CSV/JSON及附件清单导出，含ID关系、模式版本、校验值、字典和时间语义；不能只导出截图或汇总报表。

## 十二、平台应用、经营管理与合作农户

### 12.1 应用模块

| 模块 | 一期功能 |
|---|---|
| 生产工作台 | 鹿群、圈舍、饲喂、饮水巡检、消毒、粪污、任务和交接班 |
| 健康防疫 | 巡检异常、免疫、诊疗、药品、送检、隔离和限制 |
| 良种繁育 | 系谱、性能、选配、配种、妊检、分娩、断奶、选留与种鹿交付 |
| 环境设备 | 数据有效性、趋势、阈值、设备状态、校准、维护与控制审计 |
| 采茸追溯 | 采收、原料、加工交接、批次血缘、标签、报告及查询 |
| 质量库存 | 样本、待检、放行、冻结、库位、预留、出库、退货、召回 |
| 资产经营 | 生物资产台账、设备资产、订单回款、成本归集和预算偏差 |

| 管理分析 | 存栏、生产、健康、订单、现金与风险；指标可追溯到事实明细 |

大屏仅作为这些能力的只读摘要，不单独建立另一套统计口径。

### 12.2 经营指标与产能模型

- 鹿群滚动：期初 + 出生 + 引入/调入 − 死亡 − 出售/调出 ± 经批准更正 = 期末；内部跨圈转移不改变全场存栏。
- 区分成年母鹿、种公鹿、产茸公鹿、后备和幼鹿，产能受鹿舍、饲料、人员和繁育日历约束。
- 种鹿与鹿茸收入分别核算，预测和实际分栏显示；经营预测不能覆盖已确认事实。
- 成本分为直接投入、人员、场地、设备、维护、检测、物流、数字化和销售；共用成本按批准分摊规则处理。
- 经营台账服务管理决策，不替代法定会计系统；对账、期末结转和会计映射由财务负责。
- 受胎率、成活率、等级率、回款率、工单响应等保存分母和期间定义，跨版本比较明确差异。

### 12.3 农户最小数据集

农户只需填写实际发生的关键事件，不每天重复填写没有变化的信息：

1. 鹿只身份与托管/所有权确认、调入调出、出生和死亡；
2. 投入品接收与使用、日常异常、用药/防疫和兽医技术员记录；
3. 繁育、采茸、重量、交接批次与收购结果；
4. 合同、交付确认、结算确认和争议。

提供扫码、模板、离线保存、技术员代录；代录保留实际来源、代录者和农户确认，不伪装成设备自动采集。关键合法/安全字段不能因“轻量化”被删掉。

### 12.4 回购与结算

结算公式由合同确定，可按“确认重量×适用等级单价±已约定服务/调整项”计算。系统必须保留合同版本、质量分级证据、双方确认、账期、应付和实际回执。

- AI评分、数据稀疏、传感器离线不直接扣价；异常只触发复核。
- 防止用惩罚上报疾病的方式形成瞒报激励；故障、补录和争议有明确处理路径。
- 最低回购义务、产品所有权、押金保管、成本承担、死亡和保险责任在合同中分别约定。
- 平台不默认自动转账；付款经财务授权，由既有支付/银行流程执行。
- 企业回购资金不足时暂停扩户或新增承诺，按合同处理存量义务，不能靠软件“保障收益”。

### 12.5 对外查询与报送

| 通道 | 内容 | 权限 |
|---|---|---|
| 公众 | 产品和责任主体概要、标签状态、适用检测摘要、风险提示 | 最小公开集，不含农户财务、详细诊疗、个人联系方式 |
| B端客户 | 自己交付批次的来源、规格、检测、合规和物流证据 | 合同/订单绑定的对象级授权 |
| 监管 | 经确认范围的台账、报告及处置记录 | 具名授权、审计和适用报送规则 |
| 内部/合作户 | 职责范围内的个体、生产、质量和经营记录 | 角色、组织、对象、字段共同控制 |

一期保证可导出完整台账；外部监管API在接口、接收方、权限和联调通过后声明上线。报送状态包括待提交、已发送、已接收、被退回、已纠正，不能把HTTP成功当作监管业务接受。

## 十三、合规、生物安全与信息安全

### 13.1 适用规则矩阵

家养梅花鹿的管理基础参考农业农村部第303号公告所列特种畜禽范围。来源不清或涉及野生来源等情形另行审查，不纳入普通引种自动批准。

| 行为/对象 | 必须核实 | 系统行为 |
|---|---|---|
| 场地与建设 | 权属、用途、林地/生态约束、建设与环保适用手续 | 项目级准入，不以软件替代现场许可 |
| 养殖与防疫 | 主体备案、动物防疫条件及当地执行要求 | 证照台账、计划、检查和到期提示 |
| 种畜禽经营 | 经营范围、适用许可、种源与系谱交付要求 | 未具备条件不得按合格种鹿完成销售 |
| 引种与调运 | 来源、检疫、运输及跨区域要求 | 引种/出栏动作前校验适用凭证 |
| 采茸与储存 | 专业作业、用药、卫生、储存和责任要求 | SOP、权限、记录和质量限制 |
| 药用/食品/化妆品等用途 | 具体原料、工艺、用途、经营主体与渠道要求 | 产品用途白名单；未确认用途不开放相应销售模板 |
| 委托加工 | 受托主体资格、工艺、批次、质量责任和交接 | 合同与批次证据；不因委托而丢失追溯 |
| 产品标签和宣传 | 法定标识、标准采用、认证授权、宣传内容 | 模板审核；不无依据使用认证、功效或监制表述 |
| 环保/病死及废弃物 | 处理路径、人员、设施及记录 | 处置任务、回执和不可售状态 |

规则记录包含主管/确认渠道、证据、责任人、适用对象、有效期、到期动作和更改历史。适用性确认由合规与专业负责人完成，不要求每一份参考规程都成为法定标准。

### 13.2 参考标准采纳策略

| 参考内容 | V2采纳方式 |
|---|---|
| 信息采集规程 | 吸收上下游链接、基础与质量信息、责任记录和保存期思路；字段按附录A重建 |
| 编码规程 | 吸收唯一性、开放性及追溯对象分层；不默认20位短码；必要时独立兼容 |
| 标签规程 | 吸收真实、清晰、耐用、可查的原则；尺寸、防伪和标识按实际采用规则验证 |
| GB/T 33993-2024 | 涉及商品二维码符合性时核对现行正式文本，完成采用范围和测试，不只复制旧稿示例 |
| GB/T 19425-2025 | 采用相关防伪能力时核对现行正式文本及指标，不沿用旧等级宣传 |
| 鹿场净化参考资料 | 转化为专业团队评审输入；具体阈值、周期和资质按本地适用要求批准 |

### 13.3 生物安全与动物福利

- 清洁、污染、隔离和必要作业区域在底图中明确，人流、物流、动物转运路线分开管理。
- 新引入鹿、患病疑似鹿、样本、废弃物和设备维护有专门流程与记录。
- 外来人员、车辆、施工和设备维修遵守场区防疫安排；设备供应商不能因安装需要自行进入动物操作区域。
- 疫病处置由兽医及适用主管要求决定，AI不作扑杀决定。
- 对佩戴和换电池设置观察、退出、清洁及人员培训要求；装置负担随鹿只生长和季节重新评估。
- 数字围栏只辅助定位告警，不替代实体隔离、门禁及人员安全措施。

### 13.4 权限与安全控制

- 角色授权结合租户、组织、对象和字段；合作户不能横向访问其他农户数据。
- 生产、兽医、质量、经营与系统管理权限分离；系统管理员不默认拥有业务放行权。
- 质量解冻、档案合并、历史数据更正、标签批量补打及关键权限变更采用强化审核；按风险实施双人复核。
- 管理端使用强认证，关键管理/远程运维启用多因素认证、限时授权和完整审计。
- 设备身份独立管理，密钥和证书可轮换与吊销；禁止全场共用不可更换的默认口令。
- 公众服务与控制网隔离；上传文件进行类型、大小和安全检查，模型或知识助手不执行文件内指令。
- 传输加密、敏感存储加密、密钥独立保管、备份访问隔离；记录解密与导出操作。
- 对外存证或算法服务共享数据前确认用途、合同和最小必要范围，不默认上传完整诊疗、农户财务或个人信息。
- 安全事件保留证据、限制访问、按适用要求处置；上线前完成权限负向测试和应急演练。

## 十四、部署、容量、运维与接管

### 14.1 部署拓扑

```text
现场控制区：安全控制器、必要探头和执行器
       ↕ 受控接口
现场接入区：网关、边缘持久化、录像/必要推理、操作工位
       ↕ 出站加密链路/受控远程接入
中心业务区：应用、关系库、对象存储、任务与监控、备份
       ↓ 受控只读数据
对外服务区：公开追溯、B端交付、报送适配
```

中心一期优先评估由责任明确的服务方运营的专属云资源，降低场内数据库维护负担；若数据、监管或网络条件要求本地部署，可替换中心位置，但必须通过同样恢复与运维验收。农户使用统一业务服务、按域隔离，不每户独立部署数据库。

### 14.2 容量测算

以下是工程测算样例，不是已批准设备数量，也不代表耳标已经支持5分钟上报。按十进制KB/GB/TB计算。

| 样例 | 800头场景 | 1600头场景 |
|---|---:|---:|
| 每5分钟每头1条记录/日 | 230,400条 | 460,800条 |
| 每条1KB有效负载/30日 | 6.912GB | 13.824GB |
| 72小时纯有效负载 | 0.6912GB | 1.3824GB |

16路、每路2Mbps视频连续录像：总流量32Mbps，每日约345.6GB，30日约10.368TB。索引、副本、备份、日志、协议、存储冗余及峰值均另计。

因此：视频尽量本地保存并上传关键片段；本地事件缓存与录像盘分开规划。容量验收覆盖设备同时恢复造成的补传峰值，而不仅是日平均吞吐。

### 14.3 非功能目标

以下为建议冻结初值，正式合同以已批准容量、网络边界、负载和测试方法为准。

| 指标 | 建议初值与口径 |
|---|---|
| 核心业务服务可用性 | 月度≥99.5%；计划维护单列，公网/场区链路故障分别统计，不用排除项掩盖不可用 |
| 现场业务离线缓存 | 至少验证72小时实际配置数据量；关键事件本地持久化后不被轮转覆盖 |
| 核心中心数据恢复 | RPO≤1小时、RTO≤4小时；通过恢复演练验证，不宣称所有极端情况零丢失 |
| 关键感知有效数据率 | 建议≥99%，以配置预期条数、身份、校准、时效合格为分子条件；按点位和最差圈舍报告 |
| 环境本地提示 | 具备能力的链路建议P95≤60秒；包含传感器物理响应，不应用于默认小时级穿戴 |
| 召回首版影响清单 | 建议30分钟内；预先标注测试集的应受影响对象不得遗漏 |
| 常用查询 | 在批准容量和并发下建议P95≤3秒；复杂图查询及导出异步处理 |
| 公开质量提示 | 中心状态变更后立即失效相关可售缓存；状态源不可确认时显示“暂无法确认”，不返回过期可售结论 |

### 14.4 运维

监测对象至少包括：设备在线/电量/校准、最差点位数据率、边缘磁盘、积压与迟到、错误事件、数据库备份、对象原件可达、报送回执、公开码服务、模型漂移及工单无人受理。

- 日常：设备和关键告警检查，未同步关键事件处理，备份任务核查，交接班。
- 定期：仪器校准、标签耗材与备件、账号复核、恢复抽检、异常和成本复盘；周期由设备要求与风险确定。
- 变更：模式、固件、应用、规则和模型版本统一登记；先测试，再小范围，再扩大。
- 故障：现场安全优先；中心故障时保留本地控制和离线记录，暂停需中心权威批准的销售动作。

### 14.5 备份与灾难恢复

- 中心数据库有自动备份及适当增量/日志归档，独立权限与故障域；对象原件同步制定备份和版本策略。
- 恢复时校验数据库记录、附件清单与哈希、身份关系、库存余额、标签及活动限制。
- 边缘保存未同步事件至中心确认后再按策略清理；中心从较早备份恢复后，通过接收水位和幂等补传做差异核对。
- 中心在RPO范围内可能缺失的业务交易须结合审计、交接单和边缘记录重建；库存和质量状态核对完成前不恢复出库。
- 控制器配置和关键身份映射也应备份；不能只恢复看板而不能恢复现场操作。

### 14.6 更换运营商和技术供应商

合同明确数据权属、专业知识与模型使用权、开发成果和第三方许可、设备协议、域名、证书、源代码/部署包交付范围、期限及费用。

接管包至少包含：数据与附件全量导出、关系与字典、软件/固件版本、配置、接口、备份恢复手册、设备资产及校准、未结工单、活动质量限制、召回和未结订单。

接管先建立新负责人和账号，再验证查询、关键操作和公开码持续可用；不得先停服再迁移。无能力接管复杂AI时允许停用模型，保持基础台账、质量和生产安全。

每项交付记录版本、负责人、验收人、期限、依赖、费用和修改历史。新增范围必须同时修改计划、BOM、预算及验收，不能只增加功能描述。

### 15.5 历史数据迁移与切换

1. 盘点纸质、Excel、旧设备平台及现有业务记录，确认导出授权、来源、时间范围和质量。
2. 建立旧标识到永久ID的映射；无法确认的鹿、亲本、产品和设备关系进入待核，不用推测填齐。
3. 校验存栏、位置、所有权、库存、质量限制、未结订单及收付款期初数，由相应业务负责人签字。
4. 在测试区迁移并抽查附件、关系、时间和单位；旧20位码保留外部别名，不作为新批次主键。
5. 明确短期并行核对窗口及唯一记账系统，禁止新旧系统同时作为最终库存和放行事实源。
6. 切换时冻结变更窗口、补齐增量并核对期初与未结事项；确认账号、备份、工位培训和回退方案后开放正式业务。
7. 回退时先停止新交易，核对切换后新增的生产、库存和质量动作，再向目标系统补齐；不能恢复旧快照后抹去实际发运或药物限制。

历史附件和旧系统保存为受控只读证据。G4验收包含迁移对账、现场岗位演练和回退演练，不能只确认“导入成功”。

### 16.3 三年预算表基线

不沿用“暂估400万元”作为批准总额。没有正式询价和首期规模时不填伪精确金额。

| 成本类别 | 初始投入 | 第1—3年年度费用 | 核算责任 |
|---|---|---|---|
| 软件与集成 | 功能开发/采购、迁移、测试、培训 | 升级、接口、支持、许可 | 技术、采购 |
| 现场设备与施工 | 标识、探头、网关、网络、控制、工位 | 校准、维修、电池、备件、替换 | 工程、物联网 |
| 数据与AI | 首批数据整理、标签规范与基线 | 兽医/育种标注、验证、推理与维护 | 算法、专业负责人 |
| 平台运行 | 初始部署与安全设置 | 云网、备份、日志、存储、域名证书 | 运维 |
| 产品交付 | 必要打印/扫码与检测接入 | 标签、检验、物流数据、耗材 | 质量、运营 |
| 人员 | 实施期工时 | 值班、技术员、培训和故障处理 | 场长、财务 |
| 风险与退出 | 批准的预备费 | 换供应商、恢复、迁移和持续查询 | 项目、法务、财务 |

`三年TCO = 初始软硬件及施工 + 三年运行/人员/耗材/验证 + 更新替换 + 迁移退出成本`

初始费用与年度费用不重复累计；共享设备和人员记录分摊依据。预算含税口径、现金支付时点、会计资本化/费用化和折旧由财务明确。

### 16.4 财务模型衔接

既有工作簿中有不同规模和价格假设，评审已发现智能养殖研发年度行为空、租金修改记录与公式未完全一致等问题。V2不宣称这些财务问题已被改表修复。

财务负责人在G3前应：

1. 指定唯一批准模型、工作表、版本和评估日期。
2. 分别定义母鹿、种公鹿、商品公鹿及鹿茸鲜/干、等级、批发/零售价格。
3. 将BOM和年度费用映射到具体预算行，修复损坏公式并核验范围。
4. 区分租金现金支出、资产折旧、一次性投资和累计运营费。
5. 列出资金来源、到位时点、批准上限与超支处理。

模型和资金未批准，不进入整场采购。技术目标不预设第3年必然盈亏平衡。

### 16.5 收益和压力测试

`年度净增量收益 = 验证后的损失减少 + 增产贡献毛利 + 可兑现人工节约 − 新增运营费用`

- 用相同生产口径比较基线；人工时间释放不自动等于现金节省。
- 不重复累计同一次健康改善带来的各项收益。
- 必要合规和基础台账属于经营基础成本；高端感知和AI应单独证明增量价值。
- 至少测算无AI增益、无溢价、价格下降、误报增加、设备提前替换、达产延后和供应商退出。
- 没有可支持的收益时允许保留低成本台账和规则，不为维护技术叙事追加投入。

### 16.6 付款与合同

按设计确认、到货安装、集成验证、试运行、业务验收及运维交接设置付款节点，比例由采购法务批准。合同约定整改期限、缺陷处理、服务响应、验收证据、权属、接口和接管。

设备在线、界面完成、上链成功或模型能演示不能单独触发全额验收付款。

## 十七、测试、验收与上线门禁

### 17.1 分层验收

| 层次 | 可验收内容 | 不能替代 |
|---|---|---|
| 文档/设计 | 状态、数据、接口、规格和用例完备 | 现场实测、监管许可、真实收益 |
| 工程/集成 | 通信、计量、时延、缓存、联锁、恢复 | 长期模型效果和季节泛化 |
| 业务 | 一次完整生产交付、召回、结算、台账导出 | 只有页面或模拟演示 |
| 模型 | 独立数据、事件、基线、误报和安全评估 | 训练集准确率或厂商宣传 |
| 运营 | 值班、维护、预算、数据接管和持续使用 | 上线当天截图 |

测试目标在试验前冻结。未知现场参数进入决策记录；不能因测试失败事后降低标准并直接记“通过”。

### 17.2 核心验收用例

| 编号 | 范围与场景 | 必须取得的结果 |
|---|---|---|
| A01 | 永久身份：补标、换设备、重复建档、调出再调入 | 不串档、不重复计存栏；冲突进入复核，历史不丢 |
| A02 | 系谱和选配：未知父本、多候选、已知近亲、关系更正 | 不伪造确定亲本；按批准规则提示/阻断，交付证据可回溯 |
| A03 | 编码容量：同月同条件生成101个V2批次及多件标签 | 内部批次和标签唯一；若启用20位兼容，超限明确失败而非重码 |
| A04 | 标签生命周期：补打、作废、重复扫码、旧码、伪造token | 旧码显示状态，补打不解冻；公开查询不暴露后台数据 |
| A05 | 批次关系：多头合批、分装、委托加工、退货 | 关系无环、来源完整、数量差异可解释，原件可查 |
| A06 | 质量放行：待检、不合格、用途不符、限制未解除、报告不匹配 | 均不能销售出库；快检不自动等于合格 |
| A07 | 冻结并发：冻结根批次同时尝试后代出库，扣库后离场前再冻结 | 按事务先后正确阻断；未离场停止交接，已发运纳入召回，不被异步展开延迟绕过 |
| A08 | 召回：在库、在途、部分出库、部分追回及不可追回 | 预期对象全纳入，数量逐项核销；建议30分钟内出首版清单 |
| A09 | 离线：72小时缓冲、客户端重启、重复补传、冲突、缓存将满及未同步用药 | 持久化记录不被覆盖、不重记账；关键动作不离线批准；源场关键记录未对账时中心也不得放行 |
| A10 | 计量：温度对照、秤校准、身份匹配、鲜干/单位转换 | 报告误差与适用范围；不能以分辨率冒充准确度或编造个体采食量 |
| A11 | 感知：昼夜、遮挡、密集、弱网、低电和恢复峰值 | 按冻结矩阵报告有效率与P95/P99，最差点位单列 |
| A12 | 控制：断云、断网、断电、探头卡死、冲突/过期命令、急停 | 现场联锁及安全状态符合批准设计，过期命令不重放 |
| A13 | 告警工单：无人受理、跨班、误报、重复、未执行回执 | 有升级和交接；不得自动认定处置成功；关闭有复核依据 |
| A14 | AI：冻结测试集、事件不足、身份不明、漂移和服务失效 | 数据/基线/置信区间可复核；不足则不验收效果，可停用且生产不瘫痪 |
| A15 | 权限：跨农户、跨客户、公开码、运维和系统管理员越权 | 对象/字段/动作隔离，关键操作审计，管理员不能越权放行 |
| A16 | 灾备：从备份恢复数据库、附件、绑定、库存与限制 | 达到批准RPO/RTO；差异核实前不开销售出库 |
| A17 | 经营：订单、交付、回款、费用、农户结算和争议 | 数字可追明细；未签确认或未付款不记成已履约 |
| A18 | 标签环境与报送 | 低温/冷凝/摩擦后可识读；接口有回执、拒收、纠正；无接口时导出可核查 |
| A19 | 动物福利与人员安全 | 佩戴和操作有观察记录、严重伤害停用路径；供应商遵守防疫区域 |
| A20 | 迁移、接管与退出 | 期初存栏/库存/限制对账；可导出完整关系、原件、版本与未结事项，切换和回退不丢实际交易，换管理员/供应商后核心流程可继续 |

业务闭环正式验收应使用真实合法交易；尚无交易时只能进行受控模拟并标注范围，保留实际业务验收未完成状态。

### 17.3 上线门禁

- **G3采购门**：场地与业务边界、适用规则、协议、核心设计、BOM、资金及合同批准；未通过不得整场投入。
- **G4业务上线门**：身份、质量、库存、追溯、权限、恢复和人工兜底的阻断用例通过；无合规或安全阻断。
- **L2控制启用门**：独立工程与兽医/场长会签，完成A12和相关现场测试；业务软件上线不自动授权控制。
- **AI辅助启用门**：每个模型独立通过专业和效果评审；失败不阻断基础系统验收，但不得宣称模型已交付有效。
- **G5扩展门**：真实业务、成本、人员及风险满足批准条件，再增加设备、场区或合作户。

### 17.4 缺陷与变更

导致身份串档、质量绕过、不可控执行、关键数据丢失、越权或召回漏项的缺陷属于上线阻断。必须修复并回归；不能用承诺后补或风险接受替代法律、安全强制条件。

非阻断问题可有期限整改，由对应A角色签字，并明确对验收、付款及运行的影响。需求范围变更重新评估预算、时间、接口和相关测试。

## 十八、风险管理与扩展路线

### 18.1 风险台账

| 风险 | 预警信号 | 控制和止损 | 所有人 |
|---|---|---|---|
| 来源、场地或产品用途不符合条件 | 关键许可/来源不明、审核未通过 | 暂停对应引种、销售或工程，缩减边界/替换方案 | 合规负责人 |
| 设备伤害、误控或应激 | 装置相关严重异常、联锁失败 | 停用装置/自动动作，人工接管，专业复核后恢复 | 兽医、工程负责人 |
| 疫病与职业暴露 | 疑似病例、隔离异常、检测缺失 | 按批准应急和报告机制处置，系统只辅助 | 兽医负责人 |
| 批次污染或召回失败 | 来源争议、数量不平、质量状态冲突 | 冻结并扩大核查范围，不恢复未确认产品销售 | 质量负责人 |
| 感知无效或维护过重 | 低有效率、频繁换电池、人工负担增加 | 不扩大采购，改点位/模式或退回人工 | 物联网负责人 |
| 模型误报、漏报或跨场失效 | 超工单容量、严重漏报、漂移 | 停模型、规则/人工兜底，重新验证 | 算法、兽医负责人 |
| 数据不真实 | 重复建档、补录无证据、设备与实物不符 | 审核、交叉抽查、隔离低质数据，不自动罚价 | 数据、运营负责人 |
| 预算或回购资金不足 | 费用超限、报价失效、到资延迟 | 暂停扩建扩户，保留必要运营，不依赖兜底承诺 | 财务负责人 |
| 供应商停服或锁定 | 接口限制、导出不全、服务中断 | 接管、替换、停用可选能力，保持核心生产 | 技术、采购负责人 |
| 数据泄露和证据丢失 | 越权、密钥异常、恢复失败 | 隔离处置、凭据轮换、核查影响及恢复 | 安全、运维负责人 |
| 季节窗口和样本不足 | 无完整繁育/采茸周期 | 延长效果观察，不用模拟数据代替真实有效性 | 项目、算法负责人 |
| 农户纠纷与瞒报 | 异常上报减少、争议增加、结算逾期 | 申诉复核、故障免责、合同执行、暂停扩户 | 运营、法务负责人 |

每项风险记录影响范围、现有控制、残余风险、触发门槛、处置、复盘及重新启用条件；不把一次测试通过写成风险永久消失。

### 18.2 扩展准则

- 专用图库：证明复杂系谱或批次查询已超出当前实现的合理性能，并评估运维成本后引入。
- 微服务拆分：出现独立扩缩容、稳定团队边界或明确故障隔离收益时实施。
- 个体自动饲喂：具备可靠身份、计量、通道设计、低应激与安全验证后单独立项。
- 跨场模型：按设备、品种、季节和管理方式进行外部验证，不能将示范场指标直接复制。
- 对外技术产品：具有真实付费客户、交付支持、数据权利和可持续毛利后独立核算。
- 加工与文旅：执行独立合规、商业和生物安全可研，不能因系统预留接口提前承诺建设。

**一期成功的判断**：不是三类模型齐备或全场装满传感器，而是种鹿能合规交付、鹿茸可放行可追回、生产异常有人处理、经营现金和农户结算能核对、系统故障不危及现场安全。

### D.3 术语
